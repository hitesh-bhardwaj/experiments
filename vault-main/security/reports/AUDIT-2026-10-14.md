# Vault security audit — 2026-10-14

**Scope:** `vault-main` (Next.js 16.3.5 app: Clerk auth, Supabase service-role DB, Razorpay billing, effect registry and delivery), `registry/`, and the `hyperiux` CLI (`hyperiux-components/packages/cli`).
**Method:**
- White-box review of every API route, `src/proxy.js`, `next.config.mjs` and the `src/lib` auth, billing and registry modules.
- Adversarial business-logic tests run against the real route handlers, with Supabase and Clerk replaced by in-memory fakes.
- Black-box probes against local dev (`next dev`, localhost:3000).

**Baseline:** OWASP ASVS 5.0 and the OWASP API Security Top 10 (2023).
**Deliverable:** findings + repeatable tests only. No application code was changed.

## How the tests encode the findings

Every test asserts the **secure** behaviour.
- **Open finding:** its test is written as `it.fails("[ID] …")`. CI stays green while the hole exists.
- **When someone fixes it:** that test turns red, which tells them to change `it.fails` → `it`.
- **Count:** the number of `it.fails` always equals the number of open findings.
- **Verification:** every `it.fails` was flipped to `it` and confirmed to fail on an `AssertionError`, not a crash or timeout. The black-box file was included.

```bash
cd vault-main
npm run test:security                                           # white-box, hermetic (part of `npm test`)
VAULT_TEST_URL=http://localhost:3000 npm run test:security:blackbox   # live probes, read-only
cd ../../hyperiux-components/packages/cli && npm test            # CLI (security-hardening.test.js)
```

**Optional env for the live run:**
- `VAULT_TEST_FREE_TOKEN`: the `hpx_` token of a synthetic Free account.
- `VAULT_TEST_PRO_SLUG`: which Pro effect slug to probe.
- `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_ANON_KEY`: enable the read-only live RLS probe. Point it at staging, not production.

**Results on 2026-10-14:**
- `security/`: 144 pass, 44 expected-fail, 40 skipped (the env-gated live suites).
- Live, against local dev: 14 pass, 7 expected-fail.

## Verified secure (regression-guarded by passing tests)

- **Pro gating.** Anonymous callers, Free/expired/cancelled/revoked tokens, malformed bearers and slug case/alias variants never receive Pro source from `/api/cli/effects/*` or `/api/effects/*`. That holds for all 94 Pro effects. Access is decided before anything is read from disk. *(free-pro-access)*
- **Static registry.** No `/r/*.json` Pro entry carries `content`, and no Pro source appears verbatim under `public/`. *(free-pro-access)*
- **CLI tokens.**
  - Tokens are `hpx_` plus 256 bits from `crypto.randomBytes`, and only the SHA-256 hash is stored.
  - Rotating a token kills the old one, revocation kills a stolen copy immediately, and a lapsed subscription kills the token.
  - The stored hash isn't usable as a credential, and tokens are never logged. *(token-security)*
- **Razorpay webhook.** HMAC is computed over the raw body with `timingSafeEqual` and a length guard. Tampered bodies, re-serialized bodies and wrong secrets are rejected; a missing secret fails closed. Replayed charges don't double-record invoices or credits. Events for a replaced subscription can't end the upgraded plan. *(webhook-replay)*
- **verify-payment.** It re-fetches the entity from Razorpay and binds it to `notes.clerk_user_id`. User B can't claim user A's subscription or invoice. Plan ids and prices are never taken from the client. *(subscription-access)*
- **Account isolation.** Across 11 user-scoped routes and 15 handlers, every query is scoped to the session user even when another user's id arrives in body/query/headers. Victim rows are unchanged, and signed-out callers get no data and cause no writes. *(account-isolation)*
- **Admin.** All 15 admin route files refuse anonymous and Free callers with no data and no writes. The five super-admin routes refuse regular admins, admins can't self-promote, and `unsafeMetadata.role` is ignored. *(admin-idor)*
- **Templates.** Download is gated per template and per user, the response is `private, no-store`, the Blob URL never appears in the response, and traversal slugs return 404. *(download-access)*
- **Proxy.** It protects `/dashboard*`, `/api/dashboard*`, `/api/wishlist*` and the three checkout routes, including on the stale-cookie path. The dev preview cookie is inert outside `next dev`. The webhook is deliberately unprotected. *(session)*
- **Secrets.**
  - No tracked `.env`, and no live-looking keys in tracked source.
  - No `"use client"` file imports a server-secret module.
  - There is exactly one Supabase client: service-role, `server-only`. *(secrets, rls)*
- **Media proxy.** Host allowlist is HTTPS-only. Lookalike, userinfo, metadata-IP and `file:` URLs are rejected. *(security-headers, live probes)*
- **Registry integrity.** Every `files[].path/target` is relative, has no `..`, and contains no symlinks; dependencies are plain npm specs. *(registry-integrity)*

## Findings

### H1 — Regular admins can read one-time codes → full account takeover
**Status (2026-10-15): fixed.**
- `src/lib/email-redaction.js` lists the code-bearing email types.
- `sendEmail` masks the code in the subject and drops the body before logging those types.
- `/api/admin/emails` masks rows logged before the fix, in both the list and the `?id=` preview. The preview now selects explicit columns.
- `sql/redact_one_time_code_emails.sql` cleans the rows already stored.

**Where:**
- `src/app/api/admin/emails/route.js` is gated by `assertAdmin` (not super-admin). It returns `subject` in the list view and `select("*")` (including `html_content`) for `?id=`.
- `src/app/api/webhooks/clerk/route.js` forwards Clerk's `verification_code` and `reset_password_code` emails with the code in the **subject**.
- `src/lib/resend.js:71-81` logs subject and HTML to `sent_emails`.
- `api/user/send-reset-otp` emails the in-app reset OTP, and it is logged the same way.

**Impact:** any account with `role: "admin"` can start a sign-in for any address, including a super admin's, read the code from `/dashboard/admin/emails`, and sign in as that user. Regular admin is meant to be a lower-trust role, so this is privilege escalation to full takeover.
**Fix:**
- Don't persist OTP emails at all: skip logging for `email_type ∈ {verification_code, reset_password_code, password_reset_otp, magic_link}`, or redact digits in subject/body before insert.
- Purge existing rows.
- Make the HTML preview super-admin only and project explicit columns.

**Maps to:** ASVS V8 Authorization, V14 Data Protection; API5:2023 BFLA.

### H2 — Pricing-region bypass at checkout
**Status (2026-10-15): fixed.**
- `create-subscription` now takes the currency from `getVisitorCurrency()`, the same source the checkout page uses for the price it shows, and ignores `body.currency`.
- The response returns the currency it charged in.
- Upgrades still bill in the existing subscription's currency.

**Where:** `src/app/api/razorpay/create-subscription/route.js:54` sets `const currency = body?.currency === "INR" ? "INR" : "USD"`. `getVisitorCurrency()` (`src/lib/visitor-country.js`, based on `x-vercel-ip-country`) exists but checkout doesn't use it.
**Impact:** anyone can buy the INR plan. For example, Pro+ yearly costs ₹8,999 instead of $179.
**Fix:** derive the currency server-side from `getVisitorCurrency()`. If you want to honour an explicit INR request, require the geo header to agree (or a verified Indian billing address). The upgrade path already uses the existing subscription's currency.
**Maps to:** ASVS V2 Validation and Business Logic; API6:2023 Sensitive Business Flows.

### H3 — Entitlement replay and ordering
**Status (2026-10-15): fixed.**
- `shouldApplySubscriptionEvent` asks Razorpay for the subscription's current status before a start event touches a row that isn't live Pro. That covers a late event for the same subscription and one for an older subscription.
  - Real comebacks still apply, because Razorpay reports them as live: a halted payment that goes through, a resumed plan, or re-subscribing.
- verify-payment refuses a subscription that isn't `authenticated`/`active`/`trialing` (409), and re-fetches briefly while a just-paid one still says `created`. It also refuses an invoice whose status isn't `paid`.
- Event-id dedupe (L7) is still open.

**Where:**
- `src/lib/subscription-events.js:25` returns `true` whenever the event's subscription id equals the stored one, whatever the stored status.
- `markUserProFromSubscription` (`src/lib/pro-access.js:67`) writes `plan: "pro"` with the status from the event's payload snapshot.
- `src/app/api/razorpay/verify-payment/route.js`: the subscription branch never checks `subscription.status`, and the invoice branch never checks `invoice.status === "paid"`.

**Impact:**
- **Late webhook:** a redelivered `subscription.charged` (Razorpay retries for up to 24h and doesn't guarantee order) that lands after `subscription.cancelled` re-grants Pro until `current_end`.
- **Old proof:** re-posting an old, valid proof flips Clerk `publicMetadata.proAccess` back to true.
- **Unpaid invoice:** an invoice that is `issued` but not paid can still be recorded as a template purchase if a valid signature exists for that status.

**Fix:**
- Store processed `x-razorpay-event-id`s (unique) and skip duplicates.
- In `shouldApplySubscriptionEvent`, refuse `start` events when the stored row for the same id is terminal (`cancelled`/`completed`/`expired`). Alternatively, compare `event.created_at` with a stored `last_event_at`.
- In verify-payment, require `subscription.status ∈ {active, authenticated}` and `invoice.status === "paid"`.

**Maps to:** ASVS V2 Business Logic; API6:2023.

### M1 — Open redirect after authentication
**Status (2026-10-15): fixed.**
- `src/lib/safe-redirect.js` (`getSafeRedirectPath`) is now the one check for the sign-in page, the sign-up page and vault-door's `getSafeRedirectUrl`.
  - It refuses `\` and control characters.
  - It resolves the target the way a browser would, requires the same origin, and returns path + query + hash.

**Where:**
- `sign-in/[[...sign-in]]/page.js:25`
- `sign-up/[[...sign-up]]/page.js:24`
- `components/auth/AuthFormPrimitives.jsx:20` (`getSafeRedirectUrl`, used by vault-door's `router.push`)

All three check `startsWith("/") && !startsWith("//")`. `/\evil.com`, `/\/evil.com` and `/\t/evil.com` all pass, and browsers resolve them to `https://evil.com/`.
**Impact:** a crafted `…/sign-in?redirect_url=/%5Cevil.com` link lands a freshly authenticated user on an attacker page. That makes credible phishing possible, such as an "enter your card again" page.
**Fix:** one shared helper.
- Parse with `new URL(value, origin)` and require `url.origin === origin`.
- Additionally reject `\` and control characters.
- Return `url.pathname + url.search + url.hash`.

**Maps to:** ASVS V3 Web Frontend Security.

### M2 — Response hardening
**Status (2026-10-15): fixed.**
- `next.config.mjs` adds these headers on every path:
  - `frame-ancestors 'self' https://hyperiux.com https://*.hyperiux.com`, plus `X-Frame-Options: SAMEORIGIN`
  - `object-src 'none'` and `base-uri 'self'`
  - HSTS (two years, `includeSubDomains`)
  - `nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
- `remotePatterns` is now an explicit host list (`remoteImageHosts`): R2, Vercel Blob, Sanity CDN, Clerk avatars, the vault itself, Unsplash and picsum.
- The media proxy only passes video, audio and raster image types. Anything else goes out as `application/octet-stream`, with `nosniff`.
- `poweredByHeader: false` closes L13.

**Where:**
- `next.config.mjs:57-69` sets only `Content-Security-Policy: frame-src …`.
- Missing: `frame-ancestors`/`X-Frame-Options` (clickjacking on `/dashboard/settings` and the billing pages), HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `object-src`/`base-uri`.
- `remotePatterns: [{ hostname: "**" }]` makes `/_next/image` fetch any host. **Confirmed live:** the optimizer fetched `example.com`.
- `api/media-proxy` passes the upstream `content-type` through with `ACAO: *`, so an `.html`/`.svg` object in the bucket would render on the app origin.

**Fix:**
- Add `frame-ancestors 'self'` (plus `X-Frame-Options: SAMEORIGIN`), `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and `object-src 'none'; base-uri 'self'` to the CSP.
- Restrict `remotePatterns` to the real image hosts (R2, ImageKit, Sanity CDN, Cloudinary).
- In the media proxy, allowlist `video/*`/`image/(png|jpeg|webp|avif|gif)`, force `application/octet-stream` otherwise, and add `nosniff`.
- Set `poweredByHeader: false` (L13).

**Maps to:** ASVS V3, V13 Configuration; API7:2023 SSRF, API8:2023.

### M3 — In-app password reset OTP
**Status (2026-10-15): fixed.** The rules live in `src/lib/reset-otp.js`.
- **Code generation:** `crypto.randomInt`.
- **Requesting codes:** 60s between requests and 5 an hour, with a 429 and `Retry-After`.
- **Wrong guesses:** the 5th wrong guess destroys the code.
- **Comparison:** `timingSafeEqual`.
- **On success:** every other active session is revoked, and the current one is kept.
- **Known limit:** the attempt counter lives in Clerk metadata, which has no atomic increment, so a burst of parallel guesses can each read the same count. That's still at most a handful of guesses per code and 5 codes an hour. A per-user rate limit on the verify route (M6) would close it fully.

**Where:** `src/app/api/user/send-reset-otp/route.js`, `verify-reset-otp/route.js`.
- The code comes from `Math.random()`.
- There's no attempt counter: a wrong guess leaves the stored hash valid, so all 900k codes can be tried in 10 minutes.
- There's no resend cooldown.
- The compare is `!==`.
- A successful reset doesn't revoke the account's other sessions.

**Threat model:** both routes need a session, so this is escalation. A stolen cookie or an unlocked laptop becomes a permanent takeover via a password change, and the victim's other sessions stay alive.
**Fix:**
- Generate with `crypto.randomInt(100000, 1000000)`.
- Store `attempts` with the hash and burn the code after 5 failures.
- 60s resend cooldown and an hourly cap.
- `timingSafeEqual` on the hashes.
- On success, call `updateUser(..., { signOutOfOtherSessions: true })` or revoke via `sessions.getSessionList`.

**Maps to:** ASVS V6 Authentication, V7 Session Management; API2:2023.

### M4 — Abuse of unauthenticated write endpoints
**Where:**
- `api/newsletter` and `api/community/waitlist` add any address to Resend audiences with no bot check and no rate limit.
- `api/custom-animation-form`, `api/work-with-hyperiux` (removed 2026-10-16) and `api/exit-intent-invite` send branded mail to the *submitter-supplied* address. reCAPTCHA is solvable at scale, nothing limits the rate, and `name` is unbounded and goes into email subjects.
- `exit-intent-invite` also creates Clerk invitations for arbitrary addresses.

**Impact:** sender-domain reputation damage and list pollution; Vault can be used to mail third parties.
**Fix:**
- Add reCAPTCHA (or Turnstile) to the two list endpoints.
- Add a shared rate limiter, e.g. Upstash/Vercel KV keyed on `x-real-ip`. On Vercel use the platform `x-real-ip`/`x-forwarded-for`, which Vercel overwrites.
- Length-bound every field.
- Consider not sending the confirmation copy to unverified addresses.

**Maps to:** ASVS V2; API4:2023, API6:2023.

### M5 — Path traversal in the effect slug (confirmed live)
**Status (2026-10-15): fixed.**
- `getEffectSlugAliases` (`src/lib/effect-slugs.js`) now only returns slugs matching `/^[a-z0-9][a-z0-9-]{0,100}$/`, through the new `isSafeEffectSlug`.
- `registry.js` returns early when a request has no valid slug, and checks every slug-built path stays inside its registry root before any `fs` call.
- All three encoded traversals return 404 against local dev; real slugs (any case, `_` or `-`) still resolve.

**Where:**
- `src/lib/effect-slugs.js:44-59` (`normalizeSlug`) runs `decodeURIComponent` but keeps `.` and `/`.
- `getEffectSlugAliases` also returns the raw slug.
- Both feed `path.join` in `src/lib/registry.js:104` and `:322`.

**Evidence:** `GET /api/cli/effects/..%2F..%2Fpackage` with no credentials returns 200 with `vault-main/package.json` reshaped as a "free effect" (name, version, full dependency list). `%252F` and `%252e` variants work too. Any `*.json` under the deployment, and any `registry.json` reachable through the private path, can be read the same way. The 404/200 difference also leaks which files exist.
**Not affected:** no Pro bypass. A traversal to a Pro `registry.json` still carries `tier: "pro"` and is gated.
**Fix:**
- Validate the slug at the top of both delivery routes and the copy route: `/^[a-z0-9][a-z0-9-]{0,100}$/` after normalisation, otherwise 404.
- In `registry.js`, assert that `path.resolve(candidate)` starts with the registry root before any `fs` call.

**Maps to:** ASVS V5 File Handling; API8:2023.

### M6 — No rate limiting; install-quota bypass
**Where:**
- No limiter exists in `src/proxy.js` or in any route.
- `getInstallLimitDecision` returns `allowed` with no ledger entry when `isDependency` is set, and that flag comes straight from the client query `?dependency=1` (`src/lib/install-limit.js:205`).
- `x-hyperiux-device-id` is client-rotatable.
- `src/lib/request-ip.js` trusts the first `X-Forwarded-For` entry. That is safe on Vercel, which overwrites it, but spoofable on any other host.

**Impact:** latent today (`INSTALL_LIMIT_ENFORCE` unset, shadow mode). Once enforcement turns on, it's a full quota bypass.
**Fix:**
- Decide dependency status server-side: count it as a dependency only if a parent install for the same identity was recorded in the last N minutes.
- Add a per-IP request limiter on `/api/cli/*`, `/api/effects/*`, auth-adjacent routes and the public forms.

**Maps to:** API4:2023.

### M7 — `create-order` charges any client-chosen amount
**Where:** `src/app/api/razorpay/create-order/route.js:90-101`, the legacy "test payment" branch. With no `templateSlug`, it creates a live INR order for `body.amount`.
**Impact:** low today, because verify-payment grants nothing for bare orders. Still, it's an open endpoint for live charges of arbitrary size, on Vault's merchant account, for any signed-in user.

### M8 — RLS and grants are not in version control
**Where:** `sql/` declares RLS only for `template_credits`, and revokes RPC execute only for `redeem_template_credit`. These have no RLS evidence anywhere:
- **Tables:** `subscriptions`, `invoices`, `sent_emails`, `install_unlocks`, `install_events`, `cli_effect_installs`, `cli_telemetry_events`, `template_purchases`, `template_views`, `wishlisted_*`.
- **RPCs:** `claim_founding_slot`, `confirm_founding_slot`, `release_founding_slot`, `claim_install_slot`.

**Why it matters:**
- The app uses the service-role key, which bypasses RLS, so RLS is the backstop against anyone holding the anon key. That key is public by Supabase design, though Vault doesn't ship it.
- Without the rules in git they can't be reviewed, and a dashboard change goes unnoticed.

**Fix:**
- Export the live schema, then `alter table … enable row level security` on every table (with no policies, because service-role only) and `revoke all on function … from public, anon, authenticated` on every RPC.
- Commit the result to `sql/`.
- Run the live probe against staging: `SUPABASE_ANON_KEY=… npm run test:security:blackbox`.

**Maps to:** ASVS V8, V13.

### M9 — `ADMIN_EMAIL` fallback isn't tied to a verified primary address
**Where:** `src/lib/admin.js:22` matches `user.emailAddresses?.[0]?.emailAddress` and never checks verification or `primaryEmailAddressId`.
**Fix:** match the address whose `id === primaryEmailAddressId` *and* `verification.status === "verified"`. Better still, retire the env fallback now that `scripts/set-admin-role.mjs` exists.

### Low and informational
- **L1:** `admin/activity/[userSlug]` selects and returns `cli_token_hash`. Drop the column from the select.
- **L2:** `api/cli/telemetry` is unauthenticated and upserts on a client `anonymousId`, so public install counts can be inflated. Rate-limit it, and count only token-attributed or deduped-by-IP installs publicly.
- **L3:** `api/e/[id]` lets anyone mark a `sent_emails` row as clicked if they know or guess its id. Use unguessable ids or sign the link.

### CLI (`hyperiux-components/packages/cli`)
- **C1:**
  - **Where:** `src/commands/add.js:299-318`. The path guard is text-only (`path.resolve(...).startsWith(cwd)`), so if `components/` (or any target directory) is a symlink pointing outside the project, `writeFileSync` writes through it. Confirmed end to end.
  - **Fix:** `fs.realpathSync` the target directory and re-check it against `realpathSync(cwd)`, and use `lstat` to refuse to write over symlinks.
- **C2:**
  - **Where:** `src/utils/registry.js:107,157` and `src/utils/api.js:16` interpolate the effect name raw. `../secret` collapses the path, and `a?b#c` injects a query string and fragment.
  - **Fix:** `encodeURIComponent(name)`, and validate names against the slug regex before any request.
- **C3:**
  - **Where:** `fetchRegistryAsset` (`src/utils/registry.js:321-335`) checks the hostname but not the protocol, so `http://vault.hyperiux.com/...` is fetched in clear text.
  - **Fix:** require `https:`.
- **C4:**
  - **Where:** `src/utils/auth.js:16-30`. Modes 0700/0600 are applied only when the file or directory is created, so an existing world-readable `~/.hyperiux/auth.json` stays readable. `cli-state.js` shares that directory.
  - **Fix:** `chmodSync` after every write, or write to a temp file and rename it.
- **Already secure:** token file modes on first write, `logout` deleting the file, `HYPERIUX_TOKEN` taking precedence, the token never printed (only an 8+6 character preview in `whoami`), and the asset host allowlist.
